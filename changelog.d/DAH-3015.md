- `@lium.machine`: arguments and the return value travel as pickles instead of `repr()`/JSON, so numpy arrays, `Path`s, dataclasses, sets, bytes and tuples round-trip (a numpy argument used to be `NameError: array`, a numpy result `TypeError: not JSON serializable` after the GPU work was paid for). The result file comes from provider hardware, so it is loaded through a restricted unpickler: plain types, the stdlib value types (`pathlib`, `datetime`, `decimal`, `uuid`, `collections`, `enum`), numpy and the decorated function's own module reconstruct, anything else is a `RemoteExecutionError` naming the class. An exception raised on the pod is re-raised with its own type when that type is a builtin (`except ValueError` works; other types arrive as `RemoteExecutionError` with the name); its `__cause__` is the new `lium.RemoteExecutionError` with `exception_type`, `remote_traceback`, `exit_code`, `stdout`, `stderr`. The shipped source is the bare `def` (decorators and annotations removed, dedented), so methods, nested functions, `async def` and `np.ndarray` annotations run. A function that closes over variables or uses module-level names (imports, constants, helpers) is refused when decorated, with the names listed, instead of failing with `NameError` on the pod a minute and a few cents later.
