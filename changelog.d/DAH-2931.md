- CLI: `lium up --timeout SECONDS` (default 900) is the budget for the whole command — finding the node, renting it and waiting for the pod. When it runs out while the pod is still starting, exit 1 with the pod named; `--ready-timeout` now caps only the wait within that budget.
- CLI: `lium up` prints what it is doing while it waits — `renting <node>…`, `pod <name> (id: …) created; waiting for it to become ready`, then `waiting for <pod>… <STATUS> (<n> s)` on every status change and every 30 s — so an agent behind a pipe can tell a slow rent from a dead one.
- CLI: a rent request the API never answers exits 3 with `api_timeout` and says to check `lium ps` before retrying (a pod may exist); a rent the API refuses exits 3 with `rent_rejected`, the node, the server's reason, a `lium ps` check (the SDK sends the POST twice after a network failure, so a refusal can follow a rent that landed) and a pointer to `lium ls --format json`.
- SDK: `Lium.pod_events(pod_id)` (GET `/pods/{id}/events`, `[]` on a backend without the route — it ships with lium-platform#62, not yet merged, so `.cause` is `None` until then) and `Lium.pod_failure_cause(pod_id)`. `PodStartError.cause` carries the failure the backend recorded for the pod (the validator's headline, e.g. `... (failure_step: ssh_connect)`) and every `PodStartError` message ends with `; cause: ...` when there is one.
- SDK: `Lium.wait_ready(..., on_poll=callback)` reports every poll (pod, status, seconds elapsed).
